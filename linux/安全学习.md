## 特殊权限

### SUID

核心目的是解决“权限需求和安全限制之间的矛盾”，让低权限用户能临时获得高权限

### 一、SUID 的核心机制

当一个可执行文件设置了 SUID 位时，**执行该文件的用户会临时获得文件所有者的有效用户 ID（EUID）**，而非自身 ID。具体表现为：

- 若文件所有者是 root，普通用户执行时进程 EUID 变为 0（root 权限）
- 权限仅在程序运行期间有效，程序结束后自动恢复原权限
- 仅对二进制可执行文件有效，对脚本文件无效（安全限制）

在权限表示中，SUID 位会将文件所有者的执行位 (x) 替换为**s**（小写 s 表示执行位已设置，大写 S 表示执行位未设置）。例如：

```
-rwsr-xr-x 1 root root 59640 Jan 20  2022 /usr/bin/passwd
```

------

### 二、SUID 存在的根本原因

#### 1. 解决系统关键操作的权限矛盾

许多系统命令需要访问普通用户无权操作的资源：

- **修改密码**：`passwd`命令需要写入`/etc/shadow`（仅 root 可写），但必须允许普通用户修改自己的密码
- **查看进程**：`ps`命令需要读取内核进程表，普通用户无法直接访问
- **挂载文件系统**：`mount`命令需要操作内核文件系统接口，仅限 root 使用

SUID 让这些操作成为可能，同时避免直接开放 root 权限给普通用户。

### 三、典型应用场景

| 命令              | 作用                   | SUID 必要性                           |
| :---------------- | :--------------------- | :------------------------------------ |
| `/usr/bin/passwd` | 修改用户密码           | 必须写入`/etc/shadow`（仅 root 可写） |
| `/usr/bin/sudo`   | 以其他用户身份执行命令 | 允许授权用户临时获得 root 权限        |
| `/usr/bin/ping`   | 网络连通性测试         | 需要创建原始套接字（特权操作）        |
| `/usr/bin/chsh`   | 修改登录 shell         | 需写入`/etc/passwd`（root 拥有）      |
| `/usr/bin/newgrp` | 切换用户组             | 需修改进程组 ID（特权操作）           |

==**纠正误区**==

**在linux里，你敲的所有命令，本质上都不是“文字”，而是硬盘上的一个真实的，可运行的文件**

`passwd`=一个**二进制程序文件**

路径是

```
/usr/bin/passwd
```

2. 那你敲 `passwd` 时，系统在干嘛？

1. 你输入 `passwd` 回车
2. 系统去环境变量 `PATH` 里的目录挨个找
3. 找到 `/usr/bin/passwd` 这个文件
4. 加载、执行这个文件

所以：

**你运行的不是 “命令”，是 “文件”。**



### 怎么查看命令的路径

1. 最常用：`which`（找你真正执行的那个）

`which passwd`

`/usr/bin/passwd`

2. 查得更全：`whereis`

```
whereis passwd
```

会同时给出：

- 命令二进制文件
- 帮助手册

```
passwd: /usr/bin/passwd /etc/passwd /usr/share/man/man1/passwd.1.gz
```

3.  区分是不是内置命令：`type`

有些命令（如 `cd`）是 shell 自带的，**没有文件路径**，用 `type` 能看出来：

bash

```
type cd
type passwd
```

## 文件权限对应的数字

**基础权限（rwx）** + **特殊权限（SUID/SGID/ 粘滞位）**

## 一、基础权限数字（必背）

**读 r = 4**

**写 w = 2**

**执行 x = 1**

权限就是把这三个**相加**，分别对应：

**拥有者 (u) → 组 (g) → 其他人 (o)**

### 最常用完整权限

- `644` → `rw-r--r--`  普通文件默认
- `755` → `rwxr-xr-x`  程序、目录默认
- `777` → `rwxrwxrwx`  全开（极不安全）

### 二、特殊权限数字（你现在正需要）

在**最前面多一位**，也是 4、2、1：

- **4 → SUID**（Set User ID）
- 2 → SGID（Set Group ID）
- 1 → 粘滞位（Sticky）

### 跟 passwd 相关的关键例子

- `4755` = SUID + 755

  对应权限：

  ```
  rwsr-xr-x
  ```

  这就是 

  `/usr/bin/passwd` 的真实权限！



**设置SUID**

数字模式：可通过**chmod 4xxx  filename**  对文件设置SUID权限

符号模式：可通过**chmod u+s filename**  或 **chmod  u-s  filename**变更SUID



## SGID

==groupadd新建一个用户组==

**简单对比**

- `useradd`：新建**用户**
- `groupadd`：新建**用户组**

```
useradd 用户名 -G 组名
```

- 给这个新用户直接指定「附加组」（附属组）

也就是：**创建用户时，直接把他加进某个组里**

1. 小写 `-g` → 指定**主组**

2. 大写 `-G` → 指定**附加组**

`chmod g+s` 是什么意思

### 逐字母翻译

- `chmod` → 修改权限
- `g`     → 针对 **组 (group)**
- `+`     → 添加
- `s`     → 设置 **SGID 位**

`ll -d 目录` 会给你这 7 个信息：

**类型权限 → 链接数 → 所有者 → 所属组 → 大小 → 时间 → 目录名**

`ll` = `ls -l` 的别名

`ll -d` = **只看目录本身的信息，不看目录里面的文件**

**不加 SGID 的目录：**

你在里面新建文件，

这个文件的**所属组 = 你自己用户的默认组**，

跟父目录是什么组**没关系**。

如果加了的话，就变得和会和目录一样的所属组

### 怎么加SGID

chmod g+s 目录名      chmod g-s 目录名

chmod 2755 目录名          chmod 755 目录名
